# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

C3 bindings for [cgltf](https://github.com/jkuhlmann/cgltf) (single-header glTF 2.0 parser, MIT),
packaged as a C3 library (`.c3l`), not a standalone program.

- `manifest.json` provides the `cgltf` package for the `gltf` module. `"sources": [ "src/**" ]`
  replaces the default scan of the package root: a `.c3` left at the root is silently not compiled.
  `"c-sources": [ "csrc/cgltf.c" ]` compiles the cgltf implementation with the consumer's C
  compiler on every target; there is no native archive.
- `src/gltf.c3i` is the raw layer: every public cgltf type declared in full, in header order, plus
  every C function as `extern fn ... @cname("cgltf_...")`. `src/gltf.c3` is the idiomatic layer:
  the `faultdef`, `check`, and the wrappers consumers call. `src/layout.c3` is generated by
  `scripts/probe-layout.sh --update` and never edited by hand.
- `vendor/cgltf/` is the upstream header as a git submodule, pinned to a release tag. Read the real
  declaration in `vendor/cgltf/cgltf.h` before writing or changing any C3 declaration; a wrong
  field or parameter type is a silent cross-ABI memory bug.
- `test/` is a standalone consumer project. `test/libs/cgltf.c3l` is a symlink to the repository
  root because c3c resolves a dependency as `<search-path>/<name>.c3l` and scans every `*.c3l` in a
  search path, so the repository's parent directory cannot serve as the search path. `cd test &&
  c3c test` compiles the binding and runs `src/smoke.c3` against `fixtures/triangle.glb`.

## Authoring rules

- Invoke the `c3-expert`, `c3-style` and `c3-bindings` skills before writing, editing or
  reviewing any C3 or diagnosing a c3c error. C3 is 0.8.3 here and pre-1.0.
- Do not run `c3fmt`. Hand-format: K&R braces, four spaces, one fault per `faultdef` line.
- Docstrings on every public type, constant and wrapper (raw externs carry none): one summary line, `@param` for pointers and any
  parameter its name does not explain, `@return?` listing every fault. No narration.
- No development vocabulary in code: no ticket references, plan steps or milestone names.

## Binding conventions

- The `cgltf_` prefix is the module name, never part of an identifier: `gltf::parse`, not
  `gltf::cgltf_parse`. Functions `snake_case`, types `PascalCase`, constants and enum values
  `SCREAMING_SNAKE_CASE`. No `@builtin`.
- Type mapping: `cgltf_size` is `usz`, `cgltf_float` is `float`, `cgltf_int` is `int`,
  `cgltf_bool` is `int` (four bytes; C3 `bool` is one), `char*` is `ZString`, `void*` stays.
- Adjacent `T* items; cgltf_size items_count;` pairs are one `T[] items` slice field. A C3 slice is
  `{ ptr, usz len }`, so the layout is identical. `extensions_count; extensions` and
  `data_extensions_count; data_extensions` are count-first in C and stay two fields.
- Sequential enums are `enum Name : int` in header order with the prefix stripped and `MAX_ENUM`
  kept last. `cgltf_filter_type` and `cgltf_wrap_mode` carry GL enumerant values, so they are
  `typedef FilterType = int` and `typedef WrapMode = int` with cast constants.
- `cgltf_camera.data` is an anonymous union in C3; the union name does not survive.
- A raw extern whose name a wrapper takes carries the `_raw` suffix; the others keep the plain
  name. `cgltf_free` stays `free`.
- Wrappers raise faults, return slices and strings, and allocate only through a caller allocator.
  `check(Result)` maps every non-success result to its fault. `decode_base64` maps cgltf's
  `io_error` for malformed text to `INVALID_GLTF`, because bad base64 is a format error.
- The layout pins are generated: after any struct change or cgltf upgrade run
  `scripts/probe-layout.sh --update`, then `--check`. CI runs `--check` on Linux (cc) and Windows
  (cl); `scripts/abi-sizes.txt` is one file for both targets.

## Verification

```sh
scripts/probe-layout.sh --check
c3c compile-only --no-obj src/*.c3i src/*.c3 && rm -rf obj
cd test && c3c test
```
